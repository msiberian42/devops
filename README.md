## Домашнее задание к занятию «Микросервисы: подходы»

### Задача 1: Обеспечить разработку

В качестве решения для обеспечения процесса разработки подходит GitLab Cloud с GitLab CI/CD, GitLab Container Registry и GitLab Runner. 

GitLab Cloud будет обеспечивать хранение и версионирование кода. GitLab CI/CD позволяет запускать процесс сборки как автоматически при определенных событиях, так и вручную.

Для хранения данных можно использовать менеджер секретов HashiCorp Vault. В этом случае GitLab не будет хранить секреты, а будет брать их из хранилища во время выполнения задачи.

Агенты GitLab Runner позволят выполнять сборку и тестирования по CI/CD.

Таким образом, данная архитектура позволяет организовать единое облачное пространство разработки для всех микросервисов компании. Каждый микросервис будет иметь собственный Git-репозиторий и независимый Pipeline. Запуск сборок будет осуществляться автоматически при изменении исходного кода либо вручную с указанием необходимых параметров.

### Задача 2: Логи

Для организации централизованного сбора, хранения и анализа логов подходит следующий стек технологий:
- Fluent Bit — сбор логов с серверов и контейнеров.
- Apache Kafka — промежуточное хранилище и транспорт для передачи логов.
- Grafana Loki — централизованное хранение и поиск логов.
- Grafana — пользовательский интерфейс для просмотра, фильтрации и анализа логов.

Данное решение позволяет собирать логи со всех серверов, не требуя от приложений специальной интеграции с системой логирования. Приложения записывают логи в stdout и stderr, агенты Fluent Bit автоматически собирают их и передают в Kafka. Далее данные поступают в Loki, где становятся доступны для поиска через Grafana.

### Задача 3: Мониторинг

Для организации мониторинга подходит стек Prometheus, Grafana, Alertmanager + различные экспортеры. Дополнительно для мониторинга приложений, работающих в Kubernetes, предлагается использовать kube-state-metrics и cAdvisor.

- Prometheus — сбор, хранение и обработка метрик.
- Node Exporter — сбор метрик состояния серверов.
- cAdvisor — сбор метрик потребления ресурсов контейнерами.
- kube-state-metrics — получение информации о состоянии объектов Kubernetes.
- Экспортеры приложений — предоставление специфичных метрик микросервисов.
- Grafana — пользовательский интерфейс для запросов, анализа и построения дашбордов.
- Alertmanager — обработка и отправка уведомлений о проблемах.

Решение основано на модели Pull: Prometheus самостоятельно обращается к источникам метрик через HTTP и периодически получает актуальные значения.

Это позволяет централизованно собирать показатели со всех серверов и микросервисов, независимо от используемых языков программирования и технологий разработки.

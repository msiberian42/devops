### Задача 1: API Gateway

| Решение              | Маршрутизация | Аутентификация | HTTPS |
|:---------------------|:----------------------------------:|:----------------------------------:|:----------------------------------:|
| Kong Gateway         | поддерживается штатными средствами | поддерживается штатными средствами | поддерживается штатными средствами |
| NGINX                | поддерживается штатными средствами | реализуется с дополнительными настройками | поддерживается штатными средствами |
| Traefik              | поддерживается штатными средствами | реализуется с дополнительными настройками | поддерживается штатными средствами |
| Spring Cloud Gateway | поддерживается штатными средствами | поддерживается штатными средствами | поддерживается штатными средствами |
| Apache APISIX        | поддерживается штатными средствами | поддерживается штатными средствами | поддерживается штатными средствами |

Для реализации API Gateway я предлагаю использовать Kong Gateway. Что решение предоставляет все необходимые функции:
- маршрутизацию запросов на основании конфигурации;
- проверку JWT и других механизмов аутентификации;
- терминацию HTTPS;
- поддержку контейнеризации;
- расширение функциональности с помощью плагинов.
Kong Gateway позволит организовать централизованную точку входа в микросервисную архитектуру, повысить безопасность взаимодействия с внутренними сервисами и упростить управление инфраструктурой.

### Задача 2: Брокер сообщений

|                | Кластеризация | Репликация сообщений | Хранение на диске | Производительность | Поддержка различных форматов сообщений (JSON, XML, Avro, Protobuf) | Разграничение прав доступа | Простота эксплуатации |
|:--------------:|:-------------:|:--------------------:|:-----------------:|:-----------------:|:-----------------:|:-----------------:|:-----------------:|
| Kafka          | Да            | Да                   | Да                | Очень высокая     | Да | ACL на топики                      | Средняя |
| RabbitMQ       | Да            | Да                   | Да                | Высокая           | Да | ACL, vhost, permissions            | Высокая |
| Pulsar         | Да            | Да                   | Да                | Очень высокая     | Да | ACL на топики и namespace          | Средняя/низкая |
| NATS JetStream | Да            | Да                   | Да                | Очень высокая     | Да | Permissions на subjects и accounts | Высокая |
| ActiveMQ       | Да            | Да                   | Да                | Средняя/высокая   | Да | ACL и механизмы авторизации        | Средняя |

В качестве брокера сообщений я предлагаю использовать Kafka, т.к. она лучше соответствует потребностям крупной компании с большим количеством микросервисов и интенсивным обменом событиями.

Основные плюсы данного сервиса:
1. Высокая пропускная способность и эффективная работа с большими потоками данных.
2. Надёжное хранение сообщений на диске.
3. Репликация данных между узлами кластера.
4. Гибкое разграничение прав доступа через ACL.
5. Поддержка различных форматов данных.
6. Большая экосистема интеграций с системами мониторинга, обработки данных и аналитики.
